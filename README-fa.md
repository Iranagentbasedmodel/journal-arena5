# آرنا (arena-skill) — چطور در این محیط استفادهاش کنم؟

مرجع: [Jakeschincariol/arena-skill](https://github.com/Jakeschincariol/arena-skill) — مجوز MIT، ساخته‌ی Jake Schincariol.
من خودِ مخزن را خواندم و در همین سندباکس کلون و اجرا کردم؛ چیزهایی که پایین می‌بینی تست‌شده‌اند، نه حدس.

---

## ۰) اول: اصل ماجرا در یک پاراگراف

آرنا یک اسکیلِ Claude Code است. Claude Code فقط نقشِ **هماهنگ‌کننده** را دارد: با ابزار Agent، برای هر «کار»
یک ساب‌ایجنت با کانتکست تازه بالا می‌آورد، به همه‌شان یک تسک **کلمه‌به‌کلمه یکسان** می‌دهد، ولی به هرکدام یک
**کارت استراتژی** متفاوت می‌دهد (۱۵ حالت استدلال × ۱۲ ورک‌فلو × ۱۲ استراتژی = ۲۱۶۰ کارت). بعد براکتِ
حذفی اجرا می‌شود: هر دو طرف به هم حمله می‌کنند، هرکس از خودش دفاع و نسخه‌اش را اصلاح می‌کند، و یک داور
با یک **روبریک نوشته‌شده** (۵ معیار، وزن‌دار) هر دو را نمره می‌دهد. بازنده بیرون است.
۱۰۰ → ۵۰ → ۲۵ → ۱۳ → ۷ → ۴ → ۲ → ۱.

تمام دفترداریِ مسابقه در پایتون است: `bracket.py` وضعیت را در یک فایل JSON نگه می‌دارد، کارت‌ها را
پخش می‌کند، بریف‌ها را از قالب‌های داخل `SKILL.md` می‌سازد، حسابِ نمره‌ها را انجام می‌دهد و بعد از
«فشرده‌سازی کانتکست» هم می‌داند کجاست. (`next` روی دیسک نگاه می‌کند، نه در حافظه‌ی مدل.)

## ۲) راه A — همان اسکیل اصلی، در Claude Code

```text
https://github.com/Jakeschincariol/arena-skill

Install this skill, then confirm /arena works.
```

یا دستی:

```bash
git clone https://github.com/Jakeschincariol/arena-skill.git
cp -r arena-skill/skills/arena ~/.claude/skills/     # نصب سراسری، دستور می‌شود /arena
# یا داخل یک پروژه:  cp -r arena-skill/skills/arena .claude/skills/
```

سپس:

```text
/arena --quick سرتیتر صفحه‌ی قیمت ما را بازنویسی کن
/arena --agents 32 این تست فلیکی را درست کن
/arena --seed 7 هفته‌ی لانچ را برنامه‌ریزی کن
/arena            ← همین‌جوری: آخرین درخواستت را برمی‌دارد و جواب قبلی را «رقیبِ باید ببَرد» می‌کند
```

نکته‌ی مهم: این اسکیل **به Claude Code وابسته است**، چون ساب‌ایجنت‌ها را با ابزار Agent می‌سازد.
اگر Codex/ChatGPT داری، یک پورت رسمی‌طور هست: `ZephyrianDawnstrider/arena-openai`.

## ۳) راه B — همین‌جا (یا هر ماشینی) بدون Claude Code: `arena_run.py`

این فایل جای Claude Code را می‌گیرد، نه جای آرنا. یعنی همان `bracket.py` و همان `SKILL.md` و همان
کارت‌ها و همان روبریک را می‌راند، ولی هر «ساب‌ایجنت» یک فراخوانیِ مدل روی HTTP (یا یک CLI محلی) است.

### تست بی‌هزینه (بدون کلید، بدون شبکه)

```bash
cd /home/user/arena-portable
python3 arena_run.py --skill-dir /home/user/arena-skill/skills/arena \
  --provider mock --agents 12 --parallel 6 \
  --task "سه ریسک لانچ اروپا و راه کاهش هرکدام"
```

اجرا شد: ۱۲ ایجنت → ۳ دور → یک قهرمان. (`mock` فقط **ماشین** را تست می‌کند؛ جواب‌هایش بی‌ارزش‌اند.)

### اجرای واقعی

```bash
export OPENAI_API_KEY=sk-...          # یا ANTHROPIC_API_KEY / GEMINI_API_KEY
python3 arena_run.py --skill-dir /home/user/arena-skill/skills/arena \
  --provider openai --model gpt-4o-mini --quick \
  --task "..." --workdir ./run-pricing
```

پشتیبانی‌شده: هر اندپوینت سازگار با OpenAI (`--base-url`)، Anthropic، Gemini، و هر CLI که
پرامپت را از stdin بگیرد و جواب را روی stdout بدهد:

```bash
# مدل محلی با Ollama
python3 arena_run.py --provider openai --models llama3.1 \
  --base-url http://localhost:11434/v1 --api-key ollama --quick --task "..."

# هر CLI: claude -p ، llm ، ollama run ، هر اسکریپت خودت
python3 arena_run.py --provider cmd --cmd "claude -p" --quick --task "..."
```

### چیزی که اصلِ اسکیل نمی‌تواند: چند مدل در یک تورنمنت

```bash
python3 arena_run.py --provider openai --models gpt-4o,o4-mini,gpt-4o-mini \
  --base-url https://openrouter.ai/api/v1 --quick --task "..."
```

در اسکیل اصلی همه‌ی رقبا یک مدل‌اند و تنوع فقط از کارت می‌آید. اینجا می‌توانی `gpt-4o` را با
`claude` و `llama` روبه‌رو کنی و بگذاری قضاوت بین‌شان انجام شود.

### اگر وسط کار قطع شد

```bash
python3 arena_run.py --resume --workdir ./run-pricing --provider openai --model gpt-4o-mini
```

`bracket.py` کارهای تمام‌شده را از دیسک می‌خواند و فقط کارهای ناتمام را می‌خواهد. شمارنده‌ی
تلاش‌ها هم در `driver.json` ذخیره می‌شود، پس یک داورِ خراب باعث حلقه‌ی بی‌پایان نمی‌شود
(سه تلاش، بعد توقف با پیام روشن — همان قاعده‌ی خودِ SKILL.md).

### اندازه و هزینه

| تنظیم | رقبا | فراخوانی مدل | موج |
| --- | --- | --- | --- |
| `--agents 4` | ۴ | ۱۹ | ۳ |
| `--agents 8` | ۸ | ۴۳ | ۵ |
| `--quick` | ۱۶ | ۹۱ | ۱۶ |
| پیش‌فرض | ۱۰۰ | ۵۹۵ | ۷۰ |

برآورد سرانگشتی هزینه (به‌ازای هر فراخوانی حدود ۲۵۰۰–۴۰۰۰ توکن ورودی و ۱۰۰۰–۲۰۰۰ خروجی):
`--quick` روی مدل‌های کوچک ≈ یک‌دهم تا نیم دلار؛ روی مدل‌های تراز اول ≈ ۲ تا ۸ دلار.
برای همین هم `--quick` حالت روزمرّه است و ۱۰۰ تا برای وقتی که واقعاً گیر کرده‌ای.

### دو نکته‌ی محیطی

* اینترنتِ سندباکس بیرون می‌رود (تست کردم: `api.openai.com` و `openrouter.ai` پاسخ می‌دهند)، پس اجرای
  واقعی همین‌جا ممکن است — ولی کلیدی که می‌دهی داخل همین گفتگو دیده می‌شود. اگر برایت مهم است،
  همین پوشه را روی کامپیوتر خودت اجرا کن؛ اسکریپت هیچ وابستگی‌ای جز پایتون استاندارد ندارد.
* پوشه‌ی `.arena/` در اسنپ‌شاتِ این محیط **ذخیره نمی‌شود** (جزو پوشه‌های حذف‌شده است). برای همین یک
  تورنمنتِ کاملِ تمام‌شده را در `example-run/` کپی کرده‌ام تا ببینی رکوردِ نهایی چه شکلی است:
  بریف‌ها، حمله‌ها، دفاع‌ها، احکام JSON و محلول قهرمان.

## ۴) راه C — پرامپت‌تنها: `ARENA-PROMPT.md`

در همین پوشه هست. تمام کار: **کل فایل را کپی کن، بچسبان، بعد تسکت را بنویس.** (یا به‌عنوان
«دستور سفارشی/System Instruction» ذخیره‌اش کن تا همیشه در دسترس باشد.)

داخلش: بودجه‌بندی (۴/۸/۱۶ رقیب)، همان دسته‌بندی کارت‌ها، سه پاسِ حمله–دفاع–داوری، روبریک با
همان وزن‌های واقعی (درستی ۳۰، کامل‌بودن ۲۵، دقت ۱۵، مقاومت ۲۰، شفافیت ۱۰)، قاعده‌ی «نقص مرگبار»،
و قالب خروجی.

## ۵) پاسخ مستقیم به سؤال خودت

> **آیا می‌شود آن را به شکل پرامپت بازطراحی کرد؟**

بله، و `ARENA-PROMPT.md` همان است. ولی صادقانه‌اش این است:

> **«هرچند پرامپت، مدل را مجبور به اطاعت نمی‌کند.»**

درست است — و نکته‌ی اصلی هم همین است. آرنا به‌خاطر «دستور دادن» کار نمی‌کند؛ **زورِ اسکیل در پرامپت نیست،
در هارنس است.** آن‌چه فقط کد می‌تواند تضمین کند و پرامپت نمی‌تواند:

| تضمین | پرامپت‌تنها | هارنس (bracket.py / arena_run.py) |
| --- | --- | --- |
| «۱۰۰ رقیبِ مستقل» واقعاً ۱۰۰ کانتکست جداست | نه؛ مدل وانمود می‌کند | هر رقیب یک فراخوانی جدا |
| تسک برای همه کلمه‌به‌کلمه یکسان | نه، لحن هر دور عوض می‌شود | `task.md` یکتا، داخل بریف `{{task}}` |
| داور کارت‌ها را نمی‌بیند | نه، همه‌چیز در یک کانتکست است | قالب داور فقط جواب‌ها را می‌بیند |
| نمره‌ها جمعِ وزنیِ درست است | نه، حسابِ مدل تقریبی است | `decide()` در پایتون حساب می‌کند |
| کسی نمی‌تواند یواشکی دورها را کم کند | نه، فقط حرف مدل است | `next` روی دیسک نگاه می‌کند؛ نبودِ خروجی = برگشت به همان مرحله |
| وسط مسیر فراموش نمی‌کند (فشرده‌سازی کانتکست) | نه، کاملاً فراموش می‌کند | وضعیت در `arena.json` |
| جوابِ ردشده به‌صورت کور مقایسه می‌شود | نه | `final/X.md` و `final/Y.md` بدون برچسب |
| «N=۱۰۰» به «N=۶» تنزل نمی‌کند | نه، دقیقاً همین اتفاق می‌افتد | تعداد کارت‌ها و مچ‌ها در JSON ثابت است |

پس توصیه‌ی من ترکیبی است: **پرامپت برای طراحی، هارنس برای اجبار.**
اگر فقط یک چت داری، `ARENA-PROMPT.md` بهترین چیزی است که می‌شود — کیفیت را واقعاً بالا می‌برد،
ولی «۱۰۰ رقیب» در آن یک نمایش است، نه یک واقعیت. اگر می‌خواهی واقعاً ۱۰۰ بازیکن داشته باشی،
`arena_run.py` (یا خودِ اسکیل) لازم است، چون آن‌جا خروجیِ هر رقیب **یک فایل روی دیسک** است و
براکت بدون وجود آن فایل جلو نمی‌رود. اطاعت را نمی‌شود از مدل خواست؛ باید ساختارِ کار را طوری چید
که راهی جز اطاعت نباشد. این تفاوتِ پرامپتِ مؤدب و سیستمِ مقیدکننده است.

## ۶) دستورهای سریع

```bash
# نقشه و هزینه، بدون اجرا
python3 arena_run.py --skill-dir /home/user/arena-skill/skills/arena --dry-run --quick

# تورنمنت کوچک واقعی
python3 arena_run.py --skill-dir /home/user/arena-skill/skills/arena \
  --provider openai --model gpt-4o-mini --agents 8 --parallel 8 \
  --task "..." --workdir ./run1

# با جوابِ ردشده‌ی قبلی (مقایسه‌ی کورِ نهایی)
python3 arena_run.py ... --baseline-file ./old-answer.md

# ادامه‌ی یک اجرای نیمه‌کاره
python3 arena_run.py --resume --workdir ./run1 --provider openai --model gpt-4o-mini

# خواندن نتیجه‌ی یک اجرا با ابزار خود اسکیل
python3 /home/user/arena-skill/skills/arena/bracket.py winner --dir <run-dir>
python3 /home/user/arena-skill/skills/arena/bracket.py status --dir <run-dir>
```

## مهارت دوم: journal-arena (داوری سخت‌گیرانهٔ مقاله برای Energy & Buildings)

- مسیر: `skills/journal-arena/` — خط لولهٔ P0…P8 با قرارداد مدل‌ناوابسته (هر مدل زبانی،
  هر رابط چت): همهٔ حالت در فایل‌های JSON/Markdown زیر `work/`، برایف‌های خودکفا،
  اسکریپت‌های قطعی در `engine/` و دروازهٔ `validate.py`.
- سه قانون: محور (ایراد بدون `axis_link` نامعتبر)، شاهد (عین عبارت + شناسهٔ قاعده)،
  ردیابی (ویرایش فقط روی فایل جدید با `revisions.json` تأییدشدهٔ نویسنده).
- توپولوژی: حالت تقسیم ۱۲ گروه (تا ۱۰۰ ایجنت، موج‌های ۱۰تایی) + حالت آرنا برای
  ویرایش‌های مناقشه‌ای (کارت استراتژی، حذف تک‌حذفی، روبریک امتیاز).
- چک‌لیست‌های مقطرشده با شناسهٔ قاعده: راهنمای نویسندگان ENB، سیاست‌های Elsevier (AI/اخلاق/
  تعارض/بودجه)، SAGER، داده و CRediT، سبک مراجع (LTWA/CSL)، کیت سابمیت.
- دمو (بدون اعمال هیچ اصلاحی، مطابق دستور): `demo-paper/` = نقشهٔ مقاله + گزارش پیش‌بررسی
  روی `manuscript_final.txt`: ۱۲ ایراد (۲ blocker: یادداشت داخلی «REVISION NOTES» جامانده و
  نبود گرافیکال آبسترکت؛ ۵ major: چکیدهٔ ۲۷۳ واژه‌ای، ۹ کلیدواژه، خطوط غیربولت در Highlights،
  جاماندن Table 3 و Fig. 5 از شماره‌گذاری) + validation PASS.
